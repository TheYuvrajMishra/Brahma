## 4. Agent Protocol (Self-Update Instructions)

### When to update this file:
- **Learning Capture**: After any mission milestone (`Dharma`) or operational trace (`Karma`), analyze what went well or poorly, register a new `L-XXX` ID, and document the principle.
- **Optimization Issuance**: If a bottleneck, conversational friction, or code style mismatch is detected, issue an optimization ticket (`T-XXX`) under the **Behavioral Optimization Tickets** table.
- **Session Audit**: Execute a retrospective review at the end of each completed mission, logging the outcome under the **System Retrospective Log**.

### Safe Edit Guidelines:
1. **Actionable Rationale**: Learnings and tickets must state *how* the framework will change (no generic phrases like "try harder next time").
2. **Resolution State**: Once a ticket's actions are verified, set its `Status` to `RESOLVED` and file it into the archive. Do not delete resolved tickets.
3. **Reference Mapping**: Ensure all ticket rows point directly to the local URI of the modified target engine.
